Criteria

Criterios generales para mantener el trabajo claro, revisable y listo para compartir con el equipo.

  1. 1No salirse del scope del issue. PRs independientes y lo más concretas posibles por cada cambio. Evitar PRs gigantes. (Máximo 1000 líneas de código por PR)
  2. 2Evitar comentarios innecesarios. Los comentarios deberían explicar principalmente por qué se hace algo, no describir literalmente qué hace el código.
  3. 3Evitar agregar dependencias si no son realmente necesarias. La pregunta debe llegar hasta el punto de si realmente necesitamos un framework
  4. 4No dejar código comentado, console.log, logs temporales o debugging.
  5. 5Suma mucho agregar screenshots/videos en Linear cuando existen cambios visuales.
  6. 6Evitar lo más posible hardcodear algo.
  7. 7Evitar versionar en Git assets pesados, generados o dinámicos. Usar object storage/buckets para archivos grandes.
  8. 8Borrar branches una vez mergeadas, manteniendo main, dev y las branches activas.
  9. 9Usar componentes bien modularizables. No recrear la rueda cada vez; un botón con sus variantes ya basta. No utilizar márgenes, siempre paddings.
  10. 10UI, todo lo que ven los usuarios, en español. Código, front y back, todo en inglés.
